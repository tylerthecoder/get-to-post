API reference
GET /api/post
Send URL-encoded query parameters. No request body is needed on the GET. Use URLSearchParams or curl --data-urlencode so characters like &, +, #, and newlines survive correctly.

      
ParameterDefaultWhat it does

        
url required—Absolute destination URL. Public HTTPS endpoints on port 443 only. Query strings are allowed; embedded credentials and fragments are not.

        
dataEmpty bodyThe exact UTF-8 string to send. JSON, form-encoded data, GraphQL, XML, or plain text; set the matching Content-Type.

        
headers{}JSON object of string values, up to 32 entries. Content-Type defaults to application/json. Authorization, API-specific headers, and idempotency keys are supported.

        
responserawraw returns body bytes and the upstream HTTP status. json returns an envelope with status, headers, encoding, and body, using HTTP 200 when the upstream responds.

        
timeout15000Total upstream deadline in milliseconds, including DNS, connection, and response body. Integer from 1 to 20000.

      

      
JSON, forms, or plain text
The converter does not reserialize your body. To send form data, use data=name=Tyler&active=true as the parameter value and set Content-Type to application/x-www-form-urlencoded. The entire value must still be URL-encoded.
For text use text/plain; for XML use application/xml. Binary uploads and streaming are not supported.
Read the response
Raw mode exposes X-Upstream-Status and X-Upstream-Content-Type. JSON stays JSON; other text, including HTML, is served as plain text; binary data is served as a download. Arbitrary upstream headers and cookies are not forwarded.
JSON mode includes response headers (except Set-Cookie), parses JSON bodies, and encodes binary or compressed bodies as base64. encoding identifies UTF-8 or base64. This service requests uncompressed responses; if a server still compresses, raw mode returns the compressed bytes and identifies the encoding in X-Upstream-Content-Encoding.

Errors & limits
Converter errors use {"error":{"code":"…","message":"…"}}. In raw mode, upstream error bodies and statuses pass through; use X-Upstream-Status to tell them apart from converter errors.
StatusMeaning
400Invalid parameters, headers, timeout, or detected prefetch. Duplicate and unknown parameters are rejected.
401The owner enabled an optional API key and the incoming Authorization header is missing or incorrect.
403Private, local, reserved, or other special-use destination address.
405Method other than GET or OPTIONS. HEAD never sends a POST.
414Encoded request URL exceeds 12 KiB. Your client or Vercel may impose a smaller URL limit.
502DNS, connection, or TLS failure; interrupted response; or upstream response exceeds 1 MiB.
504Upstream deadline exceeded. The POST may already have been processed.

    

    
Before you use it
A GET here has side effects
Every successful invocation makes one POST. Link scanners, retries, and opening a URL again can repeat it. Responses are marked no-store, known prefetches are blocked, and redirects are never followed, but a normal GET from a scanner is indistinguishable from your request.
Use an upstream idempotency key for sensitive actions, and avoid sharing executable links. A timeout does not mean the POST was cancelled upstream.
Keep secrets out of URLs
Query parameters can appear in browser history, proxy logs, monitoring, and shared links. This server receives the destination, body, and headers. The app does not deliberately log or store them, but hosting infrastructure may log request URLs.
Avoid putting long-lived credentials or confidential data in these URLs. Prefer a direct POST or a private authenticated backend for sensitive requests.
Public endpoints only
DNS results are checked and the connection is pinned to a public IP. Localhost, private networks, metadata addresses, special-use IPs, redirects, and non-HTTPS destinations are blocked.
Host, Content-Length, Accept-Encoding, connection and proxy headers, and X-Forwarded-* / X-Vercel-* cannot be overridden. Incoming browser cookies and authorization are never copied to the destination; only explicit headers are sent.
Use responsibly
This is a public, best-effort utility with no application-level rate limit or availability guarantee. Only send requests you are authorized to make. Cross-origin GET requests are supported without browser credentials.
The owner can restrict the endpoint by setting PROXY_API_KEY on Vercel. Then clients must send Authorization: Bearer … on the GET itself, not in the URL or the upstream headers parameter.
